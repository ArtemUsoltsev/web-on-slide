# Веб на слайді (web-on-slide)

Content add-in для PowerPoint: показує будь-яку HTTPS-сторінку на слайді. Один статичний сайт, без збірки й залежностей.

| Файл | Призначення |
| --- | --- |
| `manifest.xml` | Маніфест надбудови. Завантажується в «Інтегровані застосунки» або sideload. |
| `index.html`, `app.js` | Сторінка надбудови на слайді. |
| `config.js` | Списки дозволених/заборонених доменів і спільна перевірка адрес. |
| `dialog.html`, `dialog.js` | Перехідник для діалогу Office (режим «кнопка», сайти з X-Frame-Options). |
| `vendor/qrcode.js` | Генератор QR-кодів (qrcode-generator 1.4.4, Kazuhiko Arase, MIT), без мережевих запитів. |
| `help.html` | Інструкція для доповідачів, на неї вказує `SupportUrl`. |
| `icon-32.png`, `icon-64.png` | Іконки з маніфесту. `icon-80.png` потрібна лише для AppSource. |

## Обмеження і застереження

Сторінка показується у вбудованому браузері Office: у PowerPoint для Windows це Edge (WebView2, Chromium), на Mac це Safari (WebKit), у PowerPoint для вебу це браузер глядача. Тому надбудова показує те саме, що показав би цей браузер у вбудованому фреймі.

**Працює:**
- сучасні сторінки на HTML5, CSS і JavaScript, зокрема звичайні старі HTML-сторінки без плагінів;
- відео через вбудовування (YouTube `…/embed/…`, mp4 тощо);
- інтерактивні ігри та застосунки на HTML5, Canvas і WebGL;
- голосування й опитування (Mentimeter та подібні).

**Може бути обмежено:**
- автозапуск відео зі звуком (браузер часто вимагає клік);
- повноекранний режим зсередини сторінки;
- сторінки, яким потрібен вхід в акаунт: cookies у фреймі можуть блокуватися, краще режим «У вікні».

**Не покажеться у блоці:**
- сайти, що забороняють вбудовування (заголовки `X-Frame-Options` або CSP `frame-ancestors`): Google, банки, частина соцмереж і корпоративних систем. Для них є режим «Відкривати сайт у вікні» (кнопка на слайді);
- сторінки лише на `http://` без `https://`: надбудова їх не приймає взагалі, ні в блоці, ні у вікні;
- старі технології Flash, Java-аплети, ActiveX, Silverlight: сучасні браузери їх не підтримують.

Також: під час друку й експорту в PDF замість сайту буде порожня рамка, у Teams через «PowerPoint Live» надбудови не працюють, а при поверненні на слайд сторінка завантажується заново.

## Розгортання

1. Маніфест налаштований на пілотний хостинг `https://artemusoltsev.github.io/web-on-slide/` (публічний репозиторій `web-on-slide` з GitHub Pages, гілка main, корінь). Для іншого хостингу замініть адресу в `manifest.xml` (4 місця). Продуктив: хостинг під контролем організації.
2. Перевірте маніфест: `npx office-addin-manifest validate manifest.xml`.
3. Відкрийте `https://<ваш домен>/help.html` і `https://<ваш домен>/index.html` у браузері: перша має показати інструкцію, друга повідомлення «працює лише всередині PowerPoint».
4. Sideload для тесту, потім Microsoft 365 admin center → Integrated apps → Upload custom apps.

### Оновлення

- Будь-яка зміна `manifest.xml` вимагає підняти `<Version>`; централізоване розгортання доходить до користувачів до 24 годин.
- Зміни в `app.js`, `config.js`, `dialog.js` вимагають підняти параметр `?v=` у `index.html` і `dialog.html`, інакше Office віддасть кешовану копію.
- Якщо репозиторій на GitHub Pages: захист гілки, обов'язковий рев'ю, 2FA. Хто пише в гілку, той міняє код у всіх презентаціях одразу.

### Білий список доменів

У `config.js` заповніть `allowedOrigins` (саме origin: схема + хост, без шляху). Той самий список `app.js` додає в CSP `frame-src`, тому він обмежує і переходи всередині вбудованої сторінки, не лише першу адресу. `blockedOrigins` лише не дає вставити адресу; переходів усередині сторінки він не контролює.

## Що вирішено й що лишається перевірити на пілоті

Версія 1.5 від 2026-11-09 (файли сайту, `?v=1.5.0`, маніфест і дозволи не змінювалися):

- **Кадр** (`zoom` 1–3, `fx`/`fy` 0–100): обгортка `#frameZoom` збільшується через `transform: scale()` навколо обраної точки; доступ до вмісту сторінки не потрібен.
- **Вкладки** (`tabs` JSON `[{t,u}]`, до 3, `mainTitle`): перемикач унизу блоку; `{код}` і розумні посилання працюють для кожної вкладки. Під час нового показу відкривається перша вкладка.
- **Власний текст при збої** (`offline`): показується на картці «не відповідає»; без мережі (`navigator.onLine === false`) картка з'являється одразу. У редакторі на картці є кнопка «Завжди відкривати цей сайт кнопкою».
- **Вигляд блоку** (`border`: gray/yellow/dark, `rounded`, `cornerBg`).
- **Шаблони** (`cfg.presets` у `config.js`) і **нещодавні адреси** (`localStorage`, 10 шт., лише на цьому комп'ютері).
- `cfg.check` відхиляє адреси з пробілами (Chromium мовчки приймав їх як хост із `%20`).

Версія 1.4 від 2026-11-09 (файли сайту, `?v=1.4.0`, маніфест і дозволи не змінювалися):

- **Розумні посилання** (`cfg.embedRules` у `config.js`): YouTube (watch, youtu.be, shorts, live, з таймкодом), Vimeo, Google Docs/Sheets/Slides (`/preview`), Google Forms (`embedded=true`), Google Drive (`/preview`), Miro (live-embed), Figma (embed), Canva (`?embed`). Перетворення відбувається під час показу, тож нові правила діють і для вже збережених презентацій. У вікні та в QR-коді лишається оригінальна адреса.
- **Код сесії**: `{код}` або `{code}` в адресі, окреме поле й кнопка «Код» на панелі. Код зберігається окремим ключем `code`.
- **QR-код**: режим «Лише QR-код» (`mode=qr`) і QR у куті блоку (`qr=corner`). Локальна бібліотека `vendor/qrcode.js`, CSP не змінювався.
- **Заставка «Показувати по кліку»** (`reveal`, `revealText`): сайт не завантажується до кліку; при зміні режиму перегляду заставка повертається.
- **Автооновлення** (`refresh`: 0/10/30/60/300 с): тихе перезавантаження iframe без індикатора, пауза, коли сторінка прихована.
- Перемикач «Відкривати сайт у вікні» замінено списком «Як показати» (сайт / кнопка / QR); старі налаштування `mode=embed|button` читаються як раніше.

Перевірити на пілоті: чи вистачає розміру QR у куті на проєкторі; автооновлення в PowerPoint для Mac (WebKit).

Виправлення за UI/UX-аналізом від 2026-11-09 (файли сайту, `?v=1.3.1`, маніфест не змінювався):

- Форма налаштування більше не обрізається зверху в невеликому блоці; масштаб, прокрутка й режим кнопки згорнуті в «Додатково».
- У режимі кнопки прибрано «Оновити» (воно показувало хибне «Сторінка не відповідає»).
- Індикатор «Завантажую …», поки сайт відкривається.
- Контраст панелі кнопок і межі поля адреси за WCAG AA, більші кнопки панелі.
- Помилка адреси показується одразу під полем, поле позначається як невірне й отримує фокус; Esc скасовує редагування.
- Посилання «Довідка» на формі, коротші тексти, повідомлення, якщо копіювання адреси не вдалося.
- dialog.html тепер бере ту саму версію `config.js`, що й index.html.

Оновлення вигляду від 2026-11-09 (файли сайту, маніфест не змінювався):

- Смуга прокрутки вбудованої сторінки за замовчуванням прихована (`scrolling="no"`); галочка «Показувати смугу прокрутки» на кожному слайді окремо.
- Масштаб сторінки 50–100%: iframe розкладається як на більшому екрані й зменшується, щоб сайт вміщувався в блок без прокрутки.
- Новий дизайн: панель-«пігулка» з іконками, жовті основні кнопки, екран налаштування у вигляді картки з підписом «Created by DTEK Academy».

Виправлення за аудитом від 2026-11-05 (версія 1.2.0.0):

- `Permissions` знижено до `Restricted`. Документація підтверджує Settings і `getActiveViewAsync`; `ActiveViewChanged` та діалог на цьому рівні **перевірити на пілоті**. Якщо не працюють, підняти до `ReadDocument`.
- `AllowSnapshot=false`: знімок сторінки не зберігається у .pptx. Наслідок: порожня рамка в Teams PowerPoint Live, при друці і без надбудови. Поставити `true` лише за рішенням служби безпеки.
- Єдина функція перевірки адрес у `config.js`: тільки https, без логіна/пароля, не власний домен надбудови, списки доменів, попередження про токени в запиті, автододавання `https://`.
- Захист від відсутнього office.js, відсутнього config.js і відкриття поза Office: зрозуміле повідомлення замість чорного екрана.
- `isSetSupported` для DialogApi/ActiveView; без діалогу режим «кнопка» вимкнено.
- Перевірка результату `saveAsync`; повідомлення, якщо зберегти не вдалося.
- Кнопка «Змінити» більше не скидає збережену адресу; є «Скасувати»; форма не блимає під час показу.
- Картка «Сторінка не відповідає» через 10 с без завантаження, з кнопкою «Відкрити у вікні».
- У PowerPoint для вебу діалог відкривається з `promptBeforeOpen`, щоб обійти блокувальник спливних вікон; при помилці картка з адресою для копіювання; коди 12007/12009 не викликають запасний шлях.
- CSP: `object-src 'none'`, `base-uri 'none'`, `form-action 'self'`, дозволені домени телеметрії Office; окремий CSP у `dialog.html`, скрипт винесено в `dialog.js`.
- Панель «Оновити / У вікні / Змінити» напівпрозора і займає лише місце під кнопками, щоб не перехоплювати кліки по сайту.
- Доступність: `role="alert"` для помилок, `title` iframe = домен сайту.
- `Override en-US` для назви й опису; `SupportUrl` веде на `help.html`.
- Без `catch {}` та інших конструкцій, яких немає в старих двигунах; код написаний на ES5 + `URL`.

Перевірити на пілоті (з коду не видно): діалог під час показу слайдів на кожній платформі; голосування Mentimeter у PowerPoint для вебу (сторонні cookie); проксі з автентифікацією зсередини мережі; чи пропускає проксі `appsforoffice.microsoft.com` і хостинг надбудови.
