# Розгортання для адміністраторів Microsoft 365

Інструкція для ІТ: як встановити «Веб на слайді» користувачам організації, де розмістити файли, що відкрити в проксі, як оновлювати, відкочувати й видаляти.

## 1. Вимоги

- Microsoft 365 Apps (PowerPoint для Windows з Edge WebView2, PowerPoint для Mac) або PowerPoint для вебу. Набір API: `Settings 1.1` (є в усіх актуальних версіях).
- Доступ з комп'ютерів користувачів до:
  - хостингу надбудови (зараз `https://artemusoltsev.github.io/web-on-slide/`);
  - `https://appsforoffice.microsoft.com` (Office.js) і стандартних доменів Microsoft 365 (`*.office.com`, `*.office.net`, `*.microsoft.com`);
  - сайтів, які користувачі вбудовуватимуть (або лише тих, що в білому списку).
- Якщо проксі вимагає автентифікації чи розриває TLS, перевірте, що WebView2 проходить до цих адрес так само, як Edge.

## 2. Вибір хостингу

| Варіант | Коли | Плюси | Мінуси |
| --- | --- | --- | --- |
| A. Як є: GitHub Pages автора | Пілот на кілька людей | Нічого розгортати не треба | Код змінює власник репозиторію; оновлення доходять без рев'ю ІТ; немає контролю HTTP-заголовків |
| B. Хостинг ДТЕК (рекомендовано для продуктиву) | Розгортання на організацію | ІТ розгортає лише перевірений тег; власні заголовки; білий список під контролем компанії | Треба розмістити ~1,7 МБ статичних файлів |

Для варіанта B підходить будь-який статичний HTTPS-хостинг, доступний користувачам і всередині, і поза корпоративною мережею: Azure Static Web Apps, Azure Storage (static website) + Front Door / CDN, внутрішній IIS / nginx з публікацією назовні. SharePoint для цього не підходить (не віддає HTML як сторінку).

### Як перенести на хостинг ДТЕК

1. Візьміть перевірений службою безпеки коміт чи тег (`git checkout <tag>`).
2. Скопіюйте на хостинг файли сайту (усе, крім `.git/`, `.github/`, `docs/`, `*.md`, `LICENSE`): `index.html`, `app.js`, `config.js`, `i18n.js`, `widgets.js`, `dialog.html`, `dialog.js`, `help.html`, `help-en.html`, `privacy.html`, `icon-32.png`, `icon-64.png`, `vendor/`, `timer/`.
3. У `manifest.xml` замініть `https://artemusoltsev.github.io/web-on-slide/` на нову адресу в `IconUrl`, `HighResolutionIconUrl`, `SupportUrl`, `SourceLocation` (і в коментарі вгорі).
4. Рекомендовано також:
   - згенерувати новий `<Id>` (GUID), щоб корпоративна версія не конфліктувала з пілотною, якщо хтось її вже встановив;
   - за бажанням змінити `<ProviderName>` (зараз «Artem Usoltsev»), наприклад на «Artem Usoltsev, DTEK Academy»;
   - підняти `<Version>`.
5. Перевірте маніфест: `npx office-addin-manifest validate manifest.xml`.
6. Відкрийте в браузері `https://<хостинг>/help.html` (має показати інструкцію) і `https://<хостинг>/index.html` (має написати, що працює лише всередині PowerPoint).

### HTTP-заголовки на власному хостингу

На відміну від GitHub Pages, свій сервер може додати заголовки. Рекомендовано:

- `Strict-Transport-Security: max-age=31536000`;
- `X-Content-Type-Options: nosniff`;
- `Referrer-Policy: strict-origin-when-cross-origin`;
- `Cache-Control: no-cache` для `*.html` і `manifest.xml` (JS і шрифти можна кешувати, бо в адресах є `?v=`).

**Не** ставте `X-Frame-Options: DENY/SAMEORIGIN` і `frame-ancestors 'none'`: PowerPoint для вебу показує надбудову в iframe зі своїх доменів Office, і такі заголовки її зламають. Якщо потрібен `frame-ancestors`, він має дозволяти домени Office (`https://*.officeapps.live.com`, `https://*.office.com`, `https://*.sharepoint.com` тощо) і має бути протестований у PowerPoint для вебу.

## 3. Налаштування для організації (`config.js`)

Файл змінюється на хостингу без перевстановлення надбудови.

| Параметр | Що робить | Рекомендація |
| --- | --- | --- |
| `allowedOrigins` | Білий список origin (схема + домен, без шляху), наприклад `["https://www.menti.com", "https://kahoot.it"]`. Порожній = будь-який HTTPS-сайт. Автоматично потрапляє в CSP `frame-src` | Заповнити, якщо політика ДТЕК вимагає контролю вбудованих сайтів |
| `blockedOrigins` | Заборонені сайти (діє, навіть коли білий список порожній) | За потреби; наприклад, `https://localhost` |
| `secretParams` | Параметри адреси, на які показується попередження про секрети | Можна доповнити внутрішніми назвами |
| `language` | `"auto"`, `"uk"` або `"en"` | `"auto"` або `"uk"` |
| `presets` | Кнопки «Швидкі адреси» під полем | Додати корпоративні сервіси |
| `blockTemplates` | Готові шаблони блоків для всіх | За потреби |

Після зміни `config.js` підніміть `?v=` у `index.html` і `dialog.html`.

## 4. Встановлення користувачам

### Централізоване розгортання (рекомендовано)

1. [Microsoft 365 admin center](https://admin.microsoft.com) → **Settings → Integrated apps → Upload custom apps**.
2. Тип: **Office Add-in**, завантажте файл `manifest.xml` (саме файл, а не посилання на GitHub Pages, щоб розгорталася перевірена версія).
3. Призначте користувачів або групи (для початку пілотну групу), підтвердіть розгортання.
4. Надбудова з'явиться в PowerPoint користувачів протягом кількох годин (Microsoft вказує до 24 годин): **Головна → Надбудови** (або **Вставлення → Мої надбудови → Адміністратор керує**).

Права й умови (за документацією Microsoft на момент написання; перевірте актуальні): роль Global Administrator або Exchange Administrator; користувачі мають бути в Microsoft Entra ID з ліцензією Microsoft 365 і поштовою скринькою Exchange Online.

### Пілот без адмін-центру

Мережевий каталог надбудов (Trusted Add-in Catalog): поклади `manifest.xml` у спільну мережеву папку, додати її в PowerPoint **Файл → Параметри → Центр безпеки → Параметри центру безпеки → Каталоги надійних надбудов**, позначити «Показувати в меню». Потім **Надбудови → Інші надбудови → Спільна папка**. Цей спосіб перевірено на PowerPoint для Windows. Каталоги можна роздати груповою політикою.

## 5. Оновлення

| Що змінилося | Що зробити | Коли дійде до користувачів |
| --- | --- | --- |
| Файли сайту (JS, HTML, `config.js`) | Підняти `?v=` у `index.html`, `dialog.html` і `TIMER_URL` в `app.js`, викласти на хостинг | Після перезапуску PowerPoint або повторного відкриття блоку |
| `manifest.xml` | Підняти `<Version>`, оновити маніфест в Integrated apps | До 24 годин |

Оскільки оновлення сайту діють одразу для всіх, на хостингу ДТЕК рекомендовано викладати лише теги, які пройшли рев'ю, а не гілку `main`.

## 6. Відкат і видалення

- **Відкат**: викласти на хостинг файли попереднього тегу (і, якщо змінювався маніфест, повернути попередній маніфест з вищою `<Version>`).
- **Тимчасово вимкнути**: Integrated apps → надбудова → **Turn off** або зняти призначення.
- **Видалити**: Integrated apps → надбудова → **Remove app**. Налаштування блоків лишаються у файлах презентацій, але без надбудови на слайді буде порожня рамка. localStorage можна очистити разом із даними WebView2 / браузера.

## 7. Чекліст пілоту

- [ ] Надбудова з'являється в PowerPoint після централізованого розгортання.
- [ ] Вбудовування сайту з білого списку працює; сайт поза списком відхиляється з поясненням.
- [ ] Режим «У вікні» відкривається в показі слайдів (Windows, Mac, веб).
- [ ] Проксі пропускає хостинг надбудови і `appsforoffice.microsoft.com` зсередини мережі й через VPN.
- [ ] Mentimeter / Kahoot працюють у PowerPoint для вебу (сторонні cookie).
- [ ] Презентація з 10+ блоками працює прийнятно на типовому ноутбуці.
